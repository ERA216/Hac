# Переводы по номеру телефона

Тестовый документ для проверки обобщающей способности агента. Дефекты заложены намеренно, эталон — в golden.json.

## Часть A. Новый функционал

### Общие сведения

| Поле | Значение |
| :--- | :--- |
| **Наименование задачи** | Переводы клиентам банков-партнёров по номеру телефона |
| **Продукт** | Мобильный банк, учебный кейс |
| **Бизнес-процесс** | Переводы между физическими лицами |
| **Тип работы** | Новый функционал |
| **Влияние на ИС** | Мобильный банк, платёжный шлюз, антифрод, сервис уведомлений |

### Цели
Дать клиенту возможность мгновенно перевести деньги по номеру телефона без ввода реквизитов карты.

### Архитектура решения
Мобильное приложение → сервис переводов → антифрод → платёжный шлюз. Шлюз → сервис уведомлений.

### Дизайн процесса UI
Платежи → Перевод по номеру. Поля «Телефон», «Сумма, ₸», «Сообщение». Перед подтверждением показывается полное ФИО получателя и комиссия. Кнопка «Отправить».

### Требования к изменениям

#### BPMN схема процесса
Ввод номера → поиск получателя → расчёт комиссии → антифрод → списание → зачисление → уведомление.

#### Функциональные требования
* **Ф-1.** Клиент переводит деньги со своей карты KZT получателю по номеру телефона в формате +7XXXXXXXXXX. Поддерживаемые банки получателя: Kaspi, Halyk и др.
* **Ф-2.** Сумма одного перевода — от 100 до 500 000 ₸.
* **Ф-3.** Переводы до 20 000 ₸ в месяц выполняются без комиссии. Сверх лимита взимается комиссия 1%.
* **Ф-5.** Месячный лимит бесплатных переводов обнуляется в начале месяца.
* **Ф-6.** Повторное нажатие «Отправить» не должно приводить к двойному списанию. Подробности приведены в Ф-7.

### Sequence Diagram
Приложение → сервис переводов: создать перевод. Сервис переводов → антифрод: проверить операцию. Сервис переводов → шлюз: списать и зачислить. Шлюз → уведомления: отправить push отправителю и получателю.

### Нефункциональные требования
Перевод должен проходить быстро и надёжно, сервис должен выдерживать высокую нагрузку.

### Требования к интеграции
Приложение создаёт перевод через дочерний документ «Переводы по номеру телефона — REST API».

## Часть B. REST API

Дочерний документ части A: «Переводы по номеру телефона — REST API».

### Общие параметры

| Поле | Значение |
| :--- | :--- |
| **Description** | Создание перевода по номеру телефона |
| **REST type** | GET |
| **Authorization** | Bearer, сессия клиента |
| **Request URL** | `/transfers/create` |

### Логика работы метода
1. Проверить сессию клиента.
2. Найти получателя по номеру телефона.
3. Рассчитать комиссию.
4. Отправить операцию в антифрод и списать сумму.
5. Вернуть результат перевода.

### Параметры запроса

#### Query-параметры

| Parameter | Format | Size | Mandatory | Logic | Description |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `phone` | string | 12 | Да | +7XXXXXXXXXX | Телефон получателя |
| `amount` | integer | 32 bit | Да | 1–1 000 000 | Сумма перевода, ₸ |
| `cardId` | string | 1–64 | Да | Карта клиента | Карта списания |

### Ответ
Если результат 200 — успешный. При повторе возвращается 409.

| Parameter | Format | Logic | Description |
| :--- | :--- | :--- | :--- |
| `status` | string | OK / ERROR | Результат перевода |
| `amount` | string | При успехе | Сумма перевода |
| `fee` | string | При успехе | Комиссия, ₸ |

### Статусы

**200.** Перевод выполнен.
**400.** Неверные параметры запроса.
**401.** Требуется авторизация.

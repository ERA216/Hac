### 3.2. Дефекты отдельных требований

#### 🔴 D-01. Отсутствие спецификации API-методов для чтения текущих настроек и накопленных расходов

- **Критичность:** Критично
- **Критерий:** Полнота — 29148 п. 5.2.5; IEEE 830 п. 4.3.3
- **Требования:** R-14 (Общие параметры REST API), R-10 (Требования к интеграции), R-01 (Дизайн процесса UI)
- **Где в документе:**
  - «Description | Сохранение порога. Функциональные требования: чтение порога» — *Часть B. REST API › Общие параметры, строка 103*
  - «Приложение читает и сохраняет настройки через дочерний документ «Уведомление о расходах по карте — REST API».» — *Часть A. Новый функционал › Требования к интеграции, строка 52*
  - «На экране видны переключатель, поле «Порог, ₸», сумма за месяц и кнопка «Сохранить».» — *Часть A. Новый функционал › Дизайн процесса UI, строка 29*
  - «Request URL | Dev: /alerts/saveLimit . Prod: —» — *Часть B. REST API › Общие параметры, строка 108*
- **Проблема:** В спецификации UI (L29) и описании API (L103, L52) заявлено чтение порога и отображение суммы расходов за месяц, однако в Части B описан только метод сохранения `/alerts/saveLimit`. Мобильное приложение не сможет отобразить экран настройки.

## 5. Уточняющие вопросы к автору ТЗ

**Q-01.** ⛔ *Блокирующий.* *Кому:* Аналитик · *Дефекты:* D-01 · *Требования:* R-01, R-10, R-14
В спецификации UI (L29: «На экране видны переключатель, поле «Порог, ₸», сумма за месяц…») и интеграции (L52: «Приложение читает и сохраняет настройки…») зафиксировано чтение настроек, однако в API описан только метод сохранения `/alerts/saveLimit` (L108). Какой REST API эндпоинт должен использоваться для чтения порога и расходов?

1. Добавить эндпоинт GET /alerts/getLimit?cardId=... с ответом {amount, enabled, current_expenses}
2. Использовать общий эндпоинт агрегатора карты GET /cards/{cardId}/summary
3. Разделить на два эндпоинта: GET /alerts/settings для настроек и GET /expenses/current-month для суммы

*Зачем:* Разработчики мобильного приложения не смогут реализовать экраны настроек и отображение накопленной суммы расходов за текущий месяц.
